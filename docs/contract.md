# Local-only study desk

React + Redux Toolkit + Framer Motion + Vite, Node 24 built-in SQLite. No deployment or external hosting. Graphite/silver Apple HUD, system typography, light/dark appearance, reduced motion, responsive screens. Senior data engineer, 7+ years. Thirty-day plan, sixty minutes per weekday and 150 per weekend day by default (five hours across Sat/Sun).

Content module `server/catalog.mjs` exports `subjects` and `questions`. Subject: `{id,name,short,color,description}`; IDs sql,postgres,python,pyspark,databricks. Question: `{id,subject,topic,title,difficulty,type,minutes,prompt,answer:string[],code,language,pitfalls:string[],followups:string[],sourceUrl}`. Aim 100 questions / 20 per subject with meaningful coverage, unique IDs. Realistic interview scenarios, no invented company provenance.

GET `/api/bootstrap` -> `{subjects,questions,settings,progress,plan,daily,database}`. Settings `{name,weekdayMinutes,weekendMinutes,startDate,theme}`. Progress `{sessions,attempts,drafts,bookmarks}`. Session `{id,date,subject,minutes,note,createdAt}`. Attempt `{id,date,questionId,rating,answer,note,createdAt,nextReview}` rating again/developing/confident (review 1/3/7 days). Drafts dictionary questionId:text; bookmarks array questionId. Plan array exactly30: `{day,date,subject,topic,questionIds,minutes,objective}`; distribute all questions across days with six days per subject. Daily array `{date,minutes,target,attempts}` derived from saved records. `database` relative path `.data/study.sqlite`.

Mutations return the full bootstrap snapshot: PUT `/api/settings` with changed settings; POST `/api/sessions` with session (upsert id); POST `/api/attempts` with attempt (idempotent id); PUT `/api/drafts/:id` `{text}`; POST `/api/bookmarks/:id` toggle. GET `/api/export` JSON backup; POST `/api/import` validated exported snapshot replacing user state, retaining seeded content. Bind127.0.0.1:4317, Vite5173 proxy/api. API mutations require `X-Study-Client: local` and JSON; reject foreign Origins. Validate data, preserve records on failure, use transactions. Questions/answers and records must actually reside in SQLite and be read from it.

Front end owns src/, public/, scripts/, root config, docs. Backend owns server/database.mjs, server/index.mjs, tests/database.test.mjs. Content worker owns server/catalog.mjs only. Do not edit another worker's files.
