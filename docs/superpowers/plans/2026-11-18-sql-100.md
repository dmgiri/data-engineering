# SQL 100 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for parent integration. Independent research runs in disjoint data files.

**Goal:** Make 100–200 sourced SQL study entries available locally without losing existing questions or progress.

**Architecture:** Existing catalog discovers JSON batches; SQLite inserts new IDs without overwriting existing rows. Three independent research groups author analytics, joins/coding and theory; parent authors additional supported SQL scenarios and integrates tests/docs.

**Tech Stack:** Existing React/Redux app, JSON catalog, Node SQLite; no new production dependencies or deployment.

**Spec:** docs/superpowers/specs/2026-11-18-sql-100-design.md

## Global Constraints

- Candidate-reported experiences only; no generic preparation-bank filler.
- Preserve Q&A-first UI without LinkedIn user information and all old IDs/progress.
- Direct public post provenance retained internally; independent answers cite official documentation.
- Do not attribute a company's involvement, an interview date, a role or seniority unless explicitly stated.
- Scope and dialect are explicit; no execution against existing user databases.

## Review Focus

- Repeated salary/anti-join problems under different names must not pad sourced counts.
- Quoted recommendation posts must not be attributed to the containing LinkedIn URL.
- A self-reported question list is uncorroborated; it is not an independently verified company transcript.
- SQL Server features must not be presented as portable SQL or silently translated without a label.
- New catalog rows must not change saved progress or drop old question IDs.
